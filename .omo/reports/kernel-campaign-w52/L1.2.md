## Deviations (recorded, for later lanes)

1. **Legacy columns retained in the fresh session table.** Plan sketch drops `lease_expires_at`; the unchanged write plane (`sqlite-l0-write.ts` insertSession/commitSession, owned by L3.1) still reads/writes `data`, `time_created`, `time_updated`, `lease_expires_at` and the lease-expiry predicate. Fresh schema keeps them so wave 1 runs the real code. **L3.1 must remove them together with the write-plane rework.**
2. **Delegator placement inverted vs plan.** Plan sketched module functions delegating from kernel.ts to a default kernel living in default-kernel.ts importing `makeSessionKernel` — that is a value-import cycle (kernel → default-kernel → kernel). Resolution: default-kernel.ts exports only the Storage-backed *context* (type-only import from kernel.ts, so no value cycle); kernel.ts builds and destructures the default kernel. `check-import-cycles`: 456 modules, 0 value cycles.
3. **Factory kernels have no inbox plane.** Fresh session files have no `inbox` table; `createSessionKernel` supplies no inbox adapter, so inbox reads throw and inbox writes refuse typed — fail closed by design in wave 1. Same applies to `sessions.openChildCount` (its SQL references `inbox`): callable only on the default (Storage-backed) kernel; **L3.1 must rework or remove it for per-session files.**
4. `action.prev_hash`/`action_hash` are `NOT NULL` in the fresh schema (live schema had them nullable from migration 0041); every fresh append writes both.
