## Decisions / deviations

- **D1 (deviation)**: `SessionKernelService` is NOT shipped. The boundary law's R9 refuses Context tags with zero production reads, and no wave-2 code reads the tag (every consumer receives the kernel explicitly from the activation). The tag + its `SessionEntryServices` union membership land with their first reader (handle plane, wave 3 / L3.2); union membership now would also break wave-2 providers outside every wave-2 write scope (`test/helpers/session-services.ts`, gateway composition). `services.ts` is therefore net-unchanged; the intent is documented on the `SessionKernel` interface.
- **D2**: ledger's root index does not export `openCatalogStore`/`openSessionStore` (L1.1 exported F6 only; index is L3.1/L3.2 scope). Per plan workaround the entity takes the catalog handle and an `openSession` opener through `SessionEntityContext`; handle types are derived positionally from the public `SessionHandleStore.createSessionKernel`.
- **D3 (adoption protocol)**: the catalog CAS win IS the takeover authority — adoption walks the single-increment lease CAS with `now` advanced to the held lease's expiry (inclusive-expiry `Deadline` semantics) and re-arms a far-future expiry (`2100-01-01`, +1ms per takeover) so the legacy `lease_expires_at > now` commit predicate stays satisfied until L3 deletes it. Lost CAS races re-read and re-decide; file fence ≥ target is a typed stale refusal (activation defect → mailbox returns to the cluster).
- **D4**: turn machinery and chain-guarded timer folds stay behind `SessionEntityPorts` (`runTurn`, `timers`); the entity owns receive/dedupe/fence/drain only. L2.2 implements the timer port, composition wires both.
- **D5**: request-decision intakes (`decision.receive`) are committed as received-message chain actions in the same batch instead of `commitSession`'s `receive` path — fresh session files have no inbox table; the chain is the inbox.
- **D6**: `rotateActivationFence` self-heals a materialized-but-unindexed session into the catalog from its own file row; a session absent from both planes stays a typed refusal (materialization is the handle plane's job, not the entity's).
- **D7**: no `catalog-store.ts` change was needed — L1.2's `rotateFence` (CAS + typed `SessionNotFound`) is exactly the consumed surface; adoption logic lives agent-side because the ledger index exports no helper surface to host it behind.

## Findings

- **F1 (for L3.1)**: `appendAction`'s `requestDeadline` projection inserts into an `alarm` table that fresh session files do not have — any request-state commit through a factory kernel on a fresh file will throw until the L3.1 sqlite-l0-write rework deletes that projection. Entity `RequestResolve`/`RequestCancel` are implemented but must not be exercised against fresh files before then.
- **F2 (for L3.2/L2.3)**: `packages/agent/src/index.ts` (not in this lane's scope) does not export the cluster surface; L2.4 adapted with in-package relative imports, but apps composition needs the index export.
- **F3 (coverage)**: entity request/timer dispatch paths are uncovered by this lane's test (ledger-side scope); L2.4's cluster tests (in flight, already running against this entity) cover activation/receive/drain — patch-coverage closure belongs to the wave gate, not one lane.
- **F4 (external)**: `bun script/check-effect-boundaries.ts` fails on 5× `R2_EFFECT_RUNNER` in L2.4's `packages/agent/test/cluster/entity-timers.test.ts`; this lane's own R9 finding (unread tag) was resolved by D1.
- **F5 (coordination)**: L2.4's helper assumed a `SessionClusterStorage {sessionsDir, catalogPath}` tag; that shape is unimplementable in-scope (D2 — no public store openers). Their helper has already adapted to the real `SessionEntityContext` seam mid-wave.
