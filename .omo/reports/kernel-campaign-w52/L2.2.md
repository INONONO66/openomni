## Design decisions (follow-the-code)

- **Supersede = delivery-time chain guard, never a cancel** (review F2, plan D5/D8): `settle` is a
  no-op; a redelivered `RetryScheduled` no-ops when the attempt is settled or a newer attempt intent
  exists (paged `operationChildrenPage` scan); `Deadline` no-ops on any non-open request; watch
  deliveries dedupe on `Alarm.occurrenceId` / `<watchId>:timeout:<epoch>` chain keys.
- **Arm ordering**: `retry.scheduled` chain commit strictly before the DeliverAt send; a crash
  between the two resumes from the chain, a crash in the wait is woken by redelivery.
- **`timers.ts` is self-contained**: L2.1's `messages.ts` ran concurrently, so `TimerSenders` /
  `RetryRearm` / `DeadlineArm` / `WatchTimeoutArm` are defined locally; L2.1/L2.3 wire the senders
  and `commitScheduled` over the entity client.
- **Default production retry port NOT switched** in `executor-attempts.ts` (out of scope): swapping
  it this wave would change production chain rows while gateway/worker still run the alarm table.
  L3.2 owns the switch + `executor-retry-alarm.ts` deletion; drop-in compatibility is already proven.
