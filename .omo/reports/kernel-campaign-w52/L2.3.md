## What landed

- **Cluster host in every AppLive** (`clusterHostLayer`): `SingleRunner.layer({ runnerStorage: "sql" })`
  over `SqliteClient.layer({ filename: catalogPath })` + `BunCrypto` (L1.3),
  ShardingConfig fully explicit (`entityMaxIdleTime` from `entityIdleMs`,
  100ms message/reply polls) — never `layerFromEnv` (R2/D9). Host services
  (`ClusterServices`, incl. Sharding) join `AppServices`, so entity clients run
  through the existing sanctioned runners (`runAppEffect`); the production
  runner-site count is unchanged (approved edges stay `cli/main.ts` + `gateway.ts`).
- **Session entity layer** (`sessionEntityLayer`): `SessionEntityLive` (L2.1) wired
  to a composition-owned `SessionEntityEnv` — catalog handle opened per layer
  scope and closed by its finalizer, per-session stores under
  `sessionsDir/<id>.sqlite`, chain-guarded timer port built from L2.2's real
  folds (`retry/deadline/watchFired/watchTimeout` deliveries). `runTurn` is a
  required injected port (D1).
- **Config plumbing**: `startOpenOmni` and cli `startApp` pass
  `resolveClusterStorage(...)` (L1.3) into the runtime. Injected literal test
  configs (no `catalogPath`) fall back to an in-memory catalog host, so no test
  ever touches `~/.openomni`; loadConfig-resolved boots (production, cli,
  npm-package e2e) always run the real catalog file.
- **App-level proof** (`test/cluster-runtime.test.ts`): through `AppLive` +
  entity client — Prompt appends `msg.received` at ordinal 2, redelivery
  dedupes to the same ordinal/hash, catalog fence rotates exactly once per
  activation, unknown alarm/request timers ack `noop`, first-time watch
  deliveries ack `applied`, every receive/applied-wake drains into a `start`
  decision handed to the injected turn port.

## Decisions / deviations

- **D1 (major, plan-vs-code): production ingress/boot switch-over deferred to wave 3.**
  The lane spec's end state (gateway/session delivery through the entity
  client; boot without sweep/alarm-worker) is not reachable in wave 2 without
  breaking out-of-scope surfaces: the turn machinery (`session-controller`,
  `SessionHandleStore` statics on the old `Storage.get()` singleton) migrates
  in wave 3 (L3.2/L3.3); app tests still assert alarm-worker/sweep boot
  (alarm-boot-durability, boot-wiring, monitor e2e — L3.3's write scope); and a
  wave-2 swap would split chain rows across two planes (same rationale L2.2
  recorded for the retry port). Wave-2 delivery here is: the cluster plane
  composed, booted and proven inside the production `AppLive`, with
  `sessionEntityLayer`'s `ports` as the exact seam L3.2/L3.3 fill. No stub turn
  port ships: production simply does not activate the entity until a real
  `runTurn` exists. Ingress/boot/composition scope files therefore stayed
  0-line (gateway needed no code change — `AppServices` widening flows through
  its generics).
- **D2 (scope, +22): `packages/agent/src/index.ts` cluster-surface exports.**
  Plan §2 lists this row but no post-wave-1 lane owns it, and apps/openomni
  cannot deep-import (`exports` maps `"."` only; F6 forbids deep imports).
  Additive named exports only, limited to what this lane consumes:
  `SessionEntity{,Context,Live}`, `SessionEntityEnv`, `sessionKernels`, the
  four timer delivery guards + `TimerChainReads`, and the `session-contract`
  entity port types. No concurrent-lane collision (L2.1 finished the file;
  L3.x owns other files).
- **D3 (scope, +2): `packages/ledger/src/index.ts` exports
  `openCatalogStore`/`openSessionStore`.** Plan gives these to L3.1 (wave 3),
  but the production entity env cannot be built without them and test-style
  relative deep imports are barred from app production code. Additive; L3.1
  should fold this into its index pass.
- **D4 (scope): new test file `apps/openomni/test/cluster-runtime.test.ts`.**
  The lane's write scope lists only src files, but the 100% patch-coverage DoD
  requires app-level coverage of the new composition (L2.2 flagged the same
  gap for `watch-sources.ts` and deferred to this lane/L3.3). No timing sleeps;
  all effects run through the allowlisted `runEffect`/`runAppEffect` helpers.
- **D5 (plan-vs-code): `generation-layers.ts` seed (`SessionKernelService`) not added.**
  L2.1 deliberately deferred the `SessionKernelService` Context tag to wave 3
  ("the boundary law refuses tags nothing reads", R9) — seeding a tag with no
  reader would trip R9 and pre-empt L3.2's design. The `sessionKernels`
  registry export (D2) keeps the bridge available.
- **D6: cluster boot failures are defects (`Layer.orDie`)**, not
  `AppLifecycleFailure`: `Layer.mapError` does not exist in effect
  4.0.0-rc.118, and a host that cannot open its catalog is unrecoverable at
  composition time (matches existing storage-boot defect posture).
- **D7: in-memory catalog default** (`catalogPath ?? ":memory:"`,
  `entityIdleMs ?? 60_000`) for runtimes built without cluster options keeps
  `AppServices` uniform (no conditional layer types) and every existing test
  hermetic.
