## Decisions

1. **Mid-lane L2.1 landing.** `src/cluster/{messages,session-entity,kernel-registry,timers}.ts` and the `session-contract.ts` ports landed (uncommitted) while this lane ran. The helper was rewritten from the plan-assumed API to the real surface: `SessionEntityContext`/`SessionEntityEnv` seam, `origin` = JSON of the origin *value* (entity wraps it in the EncodedPayload), `ChainAppendReceipt.deduped`, `Deadline` acks `TimerReceipt`.
2. **Test turn port.** The entity delegates turn execution to `SessionEntityPorts.runTurn`; the full executor reaches that seam in wave 3. The helper implements a minimal REAL port: chain-committed `turnIntentAction`/`turnResumeAction` + `deliveryActions` (state -> running), pluggable `TestTurnRunner`, chain-committed `turnTerminalAction` (state -> idle/interrupted), every commit under the activation's catalog fence. Recover decisions reseal the open turn — which is exactly what the crash restart test exercises.
3. **Session provisioning.** Activations refuse truly unknown sessions (`rotateFence` self-heal needs a session row), so send helpers materialize the target on demand (`kernel.materialize` + `catalog.indexSession`), memoized per session file; options flow through a `TestClusterEnv` service, not module state.
4. **Timer ports.** Wired to the real `src/cluster/timers` guards (`retryDelivery`, `deadlineDelivery`, `watchFiredDelivery`, `watchTimeoutDelivery`); `run` -> `applied`, `skip` -> `noop`.
5. **R2 probe via child processes.** `ConfigProvider.fromEnv()` snapshots `process.env` when the effect module loads, so in-process env mutation cannot exercise `layerFromEnv`. The probes run `bun -e` children whose env carries the conflicting `ENTITY_MAX_IDLE_TIME` from process start — the production hazard's real shape. The probe source is a string literal, not a repo runner site.
6. **No sleeps.** Synchronization is reply-await, `Fiber.join`, stream-marker `readUntil`, and the check2-sanctioned bounded DB/file polls (`waitUntil`, 25ms cadence, timeout as failure guard). The one `Effect.sleep(40)` in C1 is measured workload inside the runner under test (widens the overlap-detection window), not a synchronizer.

## Deviations / findings

1. **Reaper floor (R1).** `effect/cluster` `entityReaper` clamps its resolution to `>= 5000ms`, so passivation lands at ~5s regardless of `entityMaxIdleTime: 500ms`. R1's timer is scheduled 9s out so passivation demonstrably precedes the wake; a DeliverAt due before the ~5s sweep is served by the still-live activation (observed: fence unchanged, same activation). Worth noting for prod tuning: sub-5s passivation targets are not honored.
2. **F12 proxy.** `hydrateSessionHistory` parity after recovery is asserted at chain level only (real `turn` intent/terminal shapes + full hash-chain reverify in the restart child). Fold-level parity belongs to L3.2 as planned.
3. **Received-action kind.** The entity commits every received message as `kind: "prompt"` with `effect.inboxKind` discriminating prompt/interrupt/resume; idempotency is asserted via `action.id = messageId` and `deduped`, not via a `msg.received` kind (schema has none).
4. **Ordinals are chain ordinals.** Receipts are non-consecutive across messages (turn intent/delivery/terminal rows interleave); tests assert distinct + ascending, not dense.
5. **Other-lane state (not blocking, not mine).** `entity-timers.test.ts` carries 5 `R2_EFFECT_RUNNER` boundary hits (direct `Effect.runPromise`) and `kernel-registry.ts` one `R9_UNUSED_TAG`; both files run green. Left untouched per lane scope.
6. **Catalog file cohabitation confirmed.** Ledger catalog schema (via `openCatalogStore`) and cluster sql storage (via `SqliteClient`) share one catalog file without lock trouble under WAL + busy_timeout (F9).
