## `session-handle.test.ts` port notes

New harness: `testProgram(program, { policies?, seedPolicies? })` runs inside `isolated()` with a custom `IsolatedLedgerHandle` whose stores are opened with the test's `TestObservationSink` (so `dropNextCommit`/`onCommit` observe store commits). Every fixture object that owns a registry is tracked and closed in the program's `ensuring`. Test runtime defaults `closeGraceMs: 0` so teardown never burns the 30s close grace. Per-phase/per-path policy variants moved from inner `Storage.reset/initialize` re-isolations to top-level `for`-loop tests with per-test policy rows.

Deleted tests (each documented in the file header):
- lease-contention pair ("keeps the durable lease held through an ignored abort...", "reports typed lease contention...") — TTL lease acquisition deleted; successor adopts fence+1, stale writer dies at the fence CAS (conformance T11, `owner_reclaimed_before_stale_transcript_flush` cell, and the no-overlap test cover it).
- "a retained runner whose lease lapsed does not wedge the handle" — no TTL, no lapse.
- "a refused retained release surfaces once..." — the empty lease-release commit no longer exists; hibernation commits nothing.
- "heartbeat loss aborts the runner..." and "default heartbeat uses an unreferenced timer..." — heartbeat plane deleted; takeover authority is fence adoption.
- "watch installs its subscription before reading the initial snapshot" — the injectable adapter seam is deleted and `watchSnapshot` now subscribes + snapshots inside one store transaction (race closed by construction).

Key adaptations:
- Lease-held probes replaced by `expectSingleWriterUntilSettled`: pinned fence + `maximumActive === 1` is the no-takeover witness.
- `commitInbox` now rides `commitReceivedMessage(kernel, ...)` (owned sessions ride the live owner+fence; unowned adopt an ingress fence).
- Commit spies moved from the storage adapter to `spyOn(kernel(), "commit")`.
- Boot-sweep tests became per-session `reactivateSession`; crash seeds use `materialize` + `adoptFence(crashed-owner)` + pending-turn commit.
- Eager fence adoption at declare: redeclaring a hibernated session bumps the fence at declare (asserted as `fenceBeforeGet + 1` immediately, unchanged after the wake prompt).
- Worker/parent test asserts independent first fences (1 and 1) instead of the old lazy 0/1 and exact revision 9.
- "interrupted without terminal" seeds the interrupted state by riding the live activation's owner+fence with an empty action batch (adopting out-of-band over a live controller would permanently revoke its authority).

Behavior drift encoded (1): on the chain-fold plane, consuming a policy-blocked mid-turn prompt IS a delivery action bound to no turn (`turnId: "noop"`), not an absence — `deliveries("boundary-deny")` asserts the noop delivery instead of `[]`.
