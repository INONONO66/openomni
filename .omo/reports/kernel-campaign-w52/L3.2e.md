## Full-suite live-lock: bisect trail, root cause, fix

Symptom (coordinator-observed): full `bun test` spun 18 min at 100% CPU (only
clock_gettime/mach_absolute_time in `sample`), session-outbound temp SQLite files open;
session-lifecycle-conformance tests timed out mid-suite while passing alone.

| tool-capability-bridge + tool-executor-denial | 10 timeouts, exit 1 |

| tool-executor-denial ALONE | 3 pass / 2 fail (two 15s timeouts) — the source, not a victim |

Root cause: `test/tool-executor-denial.test.ts` "inherits the enclosing executor..."
called `await isolated(inner.executeCell(...))` from inside a tool body that was itself
running under `isolated(...)`. `helpers/isolated.ts` serializes every call on one
module-level `chain` promise, so the inner call queued behind the outer isolation, which
was awaiting the inner: deadlock. Because bun runs the whole suite in one process and a
bun test timeout does not cancel the stuck promise, every later `isolated()` in every
file queued behind the poisoned chain — the exact cross-file cascade (conformance,
outbound, fiber-outcome, ...) that made unrelated pairs look guilty. This was the only
nested-`isolated` site in the tree (grep over `await isolated(`/`isolatedRun(`/
`activeIsolation()`).

Fix: the nested dispatch now rides the enclosing isolation directly via
`runAgent(inner.executeCell(...))` (plain `Effect.runPromise`), with an in-file comment;
`helpers/isolated.ts` gained a doc-comment line: "NEVER nest isolated() inside a running
isolated program..." (comment-only; contract untouched).

Post-fix proof:
- tool-executor-denial alone → 5/0, exit 0.
- Parent-reported pairs re-run green: session-failure-boundaries+session-fsm → 72/0;
  session-request-recovery+session-request → 24/0; tool-dispatcher+tool-executor-denial
  → 16/0 (all exit 0). They were chain victims, not sources.
