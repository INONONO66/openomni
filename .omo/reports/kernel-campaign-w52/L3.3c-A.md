## Src changes (all in owned `apps/openomni/src/**`)

1. `src/composition/cluster-runtime.ts` - `LiveTurnEntry.ledger: SessionRunnerInput["ledger"]`:
   the live turn's own commit/transition port, published at turn start. Missing seam:
   nothing outside the runner could reach the turn's fenced transition port.
2. `src/index.ts` - facade `AppSessionHandle.requests.timeout(requestId, at)` now rides
   `entry.ledger.transition({kind:"request.timeout"}, ...)` under the turn's own fence and
   then `entry.approvals.notify(decision.request)` - exactly the deleted controller-handle
   `requests.transition` path. Fails `ExecutionApprovalError({code:"approval_authority_unavailable"})`
   when no live turn. (The earlier borrowed-authority delegation to the boot request port
   was wrong - see "Latent bug" below.)
3. `src/gateway.ts` + `src/index.ts` - shutdown join: `webSocketCallbacks` now returns
   `{ callbacks, settled }`, tracking every in-flight ws frame; `stop()` awaits
   `wsCallbacks.settled()` after `shutdownSessions`/`cells.close` and before
   `runtime.dispose()`. Missing seam: an accepted ws ingest holds a captured
   `gateway-ingress` generation for the whole ingest (the Prompt RPC runs the full turn
   inside it), so `generations.drain` raced in-flight ingests and failed with
   `GenerationUnsettled {sessionId:"gateway-ingress", owners:1}` ->
   `AppLifecycleFailure shutdown.raw_unsettled`. The old `handle.close()` was the tests'
   accidental join point; the app itself had the ordering hole.

## Root causes of the 20 fails

- 3 real: (a) terminal-seal race after interrupt (fixed with `nextTerminal()` joins),
  (b) deadline transition no-op (fixed via seam 1+2), (c) ingress-generation drain race
  (fixed via seam 3).
- 17 cascade: a failed drain leaves `processRuntime` memoized in `gatewayRuntime`, so the
  next test boots the stale runtime against a deleted temp dir -> `SQLITE_IOERR_VNODE`.
  Not changed (drain no longer fails); noted for awareness.

## Latent bug (out of lane, not fixed)

`createSessionRequests` + `requestAuthorityKernel` (boot request port): for a running
session it borrows only the *fence* while the decision inside `commitSessionRequest` is
computed under the generated `pid:request:*` owner, so `ownsRequestRevision` is false and
mid-turn transitions silently no-op. Out-of-turn (idle) adoption is unaffected. The facade
no longer uses this path mid-turn; the gateway's ws `request_answer` path mid-turn would
still hit it. Follow-up candidate.
