## Delivered surface and plain-data DTOs

There is one read surface: the app-owned `session_read` handler in
`apps/openomni/src/gateway.ts:167`. Channels parses and transports the frame;
it neither reads session storage nor derives lifecycle state. Desktop consumes
the same schemas through its existing WebSocket transport.

Every read wire DTO is Zod/plain data in
`packages/protocol/src/gateway/session-read.ts`, exported by the gateway barrel:

| Wire value | Schema | Data |
| --- | --- | --- |
| Cursor | `SessionRead.Cursor` | Nonnegative revision and activation epoch. |
| `session_read` | `SessionRead.Request` | Durable session ID, limit 1-256, optional cursor. |
| `session_snapshot` | `SessionRead.Page` | State/phase, phase time, epoch, high-water and continuation revisions, bounded redacted action identities, page-scoped attempt usage and tool wall duration. |
| `session_page` | `SessionRead.Page` | The same plain page shape, strictly after the requested revision. |
| `session_gap` | `SessionRead.Gap` | Session ID, epoch, head revision, retained-history origin. |
| Read response union | `SessionRead.Response` | Page or gap, with no runtime object or raw action payload. |
| Accepted ingress receipt | `SessionRead.Receipt` | Existing accepted receipt plus the optional existing `Gateway.IngestResult`; its admitted target binds the local view to the durable session. |

The phase schema shares the existing presentation vocabulary. The current app
reader derives its emitted phases from the durable row and latest terminal,
not from AI SDK streaming status. A read subscribes to committed-action hints
before capture; every hint causes an authoritative read. Closing the socket
removes its subscriptions. Epoch mismatch, a future revision, or an inconsistent
row/page capture yields a gap. Missing sessions use the read-only lookup and
return `session_not_found`, rather than creating a session.

Desktop `queries.ts` owns one query key per durable session ID. Cached pages
remain readable while the transport is unavailable. Lower-epoch or
lower-revision pages cannot overwrite newer authority. A gap requests a fresh
snapshot; bounded continuations are followed without accumulating an unbounded
history array in the query. LocalSession has no phase field: the merged view
has null phase until authoritative data arrives. Tabs, drafts, selection,
titles and local attention preferences remain local. `DEFAULT_PROJECT_ID`,
the Memory route, and renderer `phase: "idle"` seeds are grep-zero.

## Usage provenance

- Origin is retained at the actual provider accounting fork:
  `packages/llm/src/processor/stream-events.ts:296`. Usable provider input and
  output counts, including reported zero, yield `reported`; substitution by
  the local estimator yields `estimated`; no accounted step remains `unknown`.
  Once a multi-step attempt estimates a count, its aggregate stays estimated.
- `packages/llm/src/run.ts:291,313` carries the origin on successful evidence
  and `LlmRunFailure` respectively.
- The single durable attempt-result writer maps the origin at
  `packages/agent/src/executor-attempts.ts:140-145`, using the mapping at
  `:38-43`, and writes plain `usageProvenance`.
- `packages/agent/src/session-lifecycle/metrics.ts:22-43` reads one settled
  result per physical attempt ID. Failed billing is not counted again from
  its logical LLM parent. Unknown accounting returns null counts rather than
  manufactured reported zero. Tool wall time is the union of overlapping
  intervals, not the sum. Wire metrics are page-scoped, not session totals.

## Inspect bounds

`packages/agent/src/session-lifecycle/inspect.ts` accepts limit, revision cursor,
depth and child cursor. Limit is validated at 1-256. A shared budget bounds both
aggregate returned actions and visited sessions; every history read is a
`kernel.historyPage` with no more than the remaining budget.

Descendants are discovered through indexed, keyset-paged catalog reads:
`CatalogStore.childSessionsPage`, exposed by the kernel, and opened through the
existing runtime `openKernel`. No `kernel.listRows` or loop-to-head remains in
inspection. `nextCursor` resumes history; `nextChildrenCursor` resumes child
discovery, with the root cursor advanced to its captured head. Returned child
pages also carry their own continuations. The shared-file test fixture now
registers its sessions in the real catalog, matching app composition.

The >256-action regression appends 300 actions and observes 256 then 44 root
transitions, discovers the commissioned child through the catalog, and asserts
zero `kernel.listRows` calls at depth 1. Existing causal, policy-redaction,
pure-read and context-restoration tests still pass. This does not claim that
the separate full model-context hydration result is aggregate-bounded.
