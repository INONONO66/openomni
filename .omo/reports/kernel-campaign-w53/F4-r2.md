# Lane F4-r2 receipt — overlapping session reads keep every waiter

Fixes review-r2 finding 4: `reads.set(sessionId, ...)` silently replaced an
existing waiter, so the first `readSession()` promise could never settle,
including after socket close.

## Fix

`apps/desktop/src/renderer/chat/gateway-transport.ts`:

- The `reads` map entry now carries a `cursorKey` (caller-supplied initial
  cursor, `""` for none) and a `waiters` list instead of a single
  resolve/reject pair.
- A second `readSession` with the same session + cursor coalesces onto the
  in-flight entry (no second wire request); every waiter resolves from the
  final page.
- A second `readSession` with a differing cursor is rejected explicitly with
  the new exported typed error `SessionReadSupersessionError` instead of
  silently replacing the entry; the in-flight read keeps its waiters.
- Session-scoped error frames, socket close, and socket error (`drain`) now
  reject **every** waiter; success resolves every waiter. Send failure on the
  entry-creating read still deletes the entry and rejects its waiter.
- New top-level helper `rejectWaiters` keeps `drain` under the ultracite
  cognitive-complexity limit.
- `bindSession` untouched (lane F1-r2 ownership; F1-r2's `session_bound`
  edits landed in this file concurrently, non-overlapping).

## Tests added

`apps/desktop/test/gateway-transport.test.ts`, in the "session reads over the
gateway socket" describe, all against a real Bun WebSocket server that holds
its response behind an explicit release (no sleeps; every wait is an event):

1. `two concurrent identical reads coalesce onto one request and both resolve`
   — one wire request, both promises resolve to the same terminal page.
2. `a differing-cursor second read is rejected while the first still resolves`
   — second read rejects with `SessionReadSupersessionError` (name + message
   asserted); first read still resolves; still one wire request.
3. `a close drains every coalesced waiter` — `server.stop(true)` rejects both
   coalesced waiters with `gateway socket closed unexpectedly`.

Mutant proof: removing the coalesce/supersession branch (restoring the old
silent-replace behavior) made both coalesce-named tests fail (0 pass, 2 fail,
exit 1 — the lost first waiter times out exactly as finding 4 describes);
the mutant was then reverted by re-applying the fix and the full file passes.
Evidence: `F4-r2-artifacts/mutant-run.txt`.
