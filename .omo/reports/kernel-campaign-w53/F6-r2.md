## Root cause

Hosted failure `(fail) fresh-process refuses tampered checkpoint foldVersion
before writes [5002.47ms]` / `error: timed out waiting for reconstruction
write` was the `bounded()` helper's **default 5000 ms deadline** firing on the
`child("write", ...)` wait — the label `reconstruction ${stage}` with stage
`write`, i.e. the write-stage child, not a wait for a write the refusal path
never performs. The test already subscribes to the exact completion signal
(`process.exited` plus draining both pipes; `process.exited` settles even for
an already-exited child, so there is no subscribe-after-exit race). On a cold
CI runner, spawning a fresh bun child, booting it, replaying the fixture
(>256 revisions), and exiting exceeded 5000 ms; locally the same child takes
0.4–2.4 s (measured this session: write 2.4 s worst). `packages/agent`
`test:ci` uses `--timeout 15000`, so bounded's 5000 ms fired first, exactly at
5002 ms. No product race exists; `packages/agent/src` was not touched.

## Fix (deterministic, no sleeps)

`packages/agent/test/durable-reconstruction.test.ts` only:

- New `childDeadlineMs = 60_000` constant with a comment; `child()` now passes
  it to `bounded(...)` (still awaiting the exact exit+drain signal, never a
  sleep) and labels the wait `reconstruction ${stage} child exit` so a future
  CI timeout names the real awaited signal.
- Explicit per-test timeouts sized above the worst-case sum of child
  deadlines, so bun's per-test timeout can never undercut the labeled bound:
  the 6-child replay test gets `6 * childDeadlineMs + 30_000`, each 2-child
  tampered-checkpoint test gets `2 * childDeadlineMs + 30_000`. The refusal
  (wake) path needs no different signal: the child writes its
  FoldCheckpointIntegrityError witness file and exits 1, and `child()` already
  waits on that exit.
- Ultracite reformatted the `test(...)` calls (multi-line) after the timeout
  argument was added; the large diff line count is that rewrap.
