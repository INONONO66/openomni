## Scope and method

This QA used the production composition root (`startOpenOmni` from `apps/openomni/src/index.ts`), not test fixtures or unit-test mocks. A temporary Bun script supplied only a fake model transport so the real Resident, catalog, dispatcher, placement gate, WebSocket route, machine host, IPC daemon, and Python cell kernel could run. No source files were changed.

Exact invocation (working directory `/Users/ino/Develop/openomni-toolarch`):

```text
bun /tmp/qa-c002.ts 2>&1 | tee /Users/ino/Develop/openomni-toolarch/.omo/reports/tool-arch-impl/qa-c002-execution.txt
```

The script booted two real composition roots. The first enrolled `offline-machine` with `kernel.py` but attached no daemon, then opened an authenticated loopback WebSocket and sent `{"type":"message","text":"exercise model door"}`. Its injected model run called the real agent-door executor with malformed `delegate`, `unknown_tool`, and `run_code` targeting the unattached machine. The second boot enrolled `alpha`, attached a real `attachMachineDaemon` offering `kernel.py`, opened another authenticated loopback WebSocket, and sent `{"type":"message","text":"exercise cell door"}`. Its model run called real `run_code`; the Python cell called `tool.delegate()` with invalid input and caught the resulting `ToolError`.
