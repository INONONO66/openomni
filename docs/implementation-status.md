| Machine filesystem (read-only) | implemented and wired | `packages/protocol/src/machine/`, `packages/machines/src/{fs,host,daemon}.ts`, `apps/openomni/src/machines/vfs.ts`, `apps/openomni/src/tools/machine-fs.ts` | Attached machines are one flat `/machines/<machineId>/<export>/<path>` namespace with a read-only slice (`docs/machines-and-delegation.md` §2.1): `fs_read`/`fs_list`/`fs_stat`, host-placed and offered to the model and to cells alike, but NOT over the same namespace: the model door holds the whole flat namespace (Owner authority), while a cell's catalog is bound at the composition root to the machine `run_code` dispatched it to, and a cell-originated `fs_*` path naming any other machine refuses as a typed `cross_machine_denied` before the host is reached. One capability, `fs.read`, gates all three. Reach is `Enrollment.allowedExports ∩ Offer.exports` (`Machine.effectiveExports`), both additive-optional and both defaulting to empty, so a pre-VFS peer on either side grants nothing; the offer carries export NAMES only, never the daemon-local directory behind them. Enforcement is layered: the host checks attachment, capability, and the effective export set before the wire, and the daemon re-checks its own offer and owns path confinement — descriptor-anchored, not pathname-checked: the export root is opened once and every request's components are walked relative to that descriptor with no link followed, so check and use are one decision rather than a race. Any resolution landing outside the root refuses uniformly as `path_escapes_export` whether or not the outside target exists, so the reason set cannot be read as an existence oracle. A daemon asked for a capability it never offered answers with a transport-level protocol error (`MachineDaemonProtocolError`, reason `capability_not_offered`), not an `FsResult` refusal: that is a host violating the attachment it negotiated, not a caller inside the contract; an export name absent from its own `Offer.exports` stays inside the contract and refuses as typed `export_not_available` (`docs/machines-and-delegation.md` §2.1). `FsRequest` paths are relative and the schema refuses leading `/`, `..`, and NUL as a first gate; `FS_READ_MAX_BYTES`/`FS_LIST_MAX_ENTRIES` are protocol-owned and daemon-enforced, with `truncated` reported rather than a prefix passed off as the whole. Refusals reach both doors as thrown typed errors (`MachineVfsError`), so a cell sees a catchable `ToolError` instead of refusal text it might store as data. The composition root wires the surface only when some enrollment names an export, and `machines` reports each attachment's effective exports as the paths the tools accept. |

## Planned, not implemented

- Transactional outbox projection from authoritative message/state writes to Bus observation; current session-message events are emitted after the durable transaction and therefore do not close the post-commit crash window.
- Dynamic component/plugin composition with reactive dependencies; reversible registration ownership ships as the app's composition substrate (`apps/openomni/src/composition/composer.ts`), which owns boot rollback and shutdown as one reverse-order release, and generation draining ships for delegation drivers (`apps/openomni/src/composition/driver-registry.ts`): the kernel resolves drivers per dispatch from the live registry, a swap pins in-flight work to the generation that accepted it, and `drain()` resolves exactly when that generation's last run returns. Channel surfaces are composed components: `apps/openomni/src/channels.ts` is a declarative profile (one row per configured channel), each row mounts as its own composition stage, and disposal revokes exactly what the component registered — its listener, its outbound delivery route (live-map registration read per delivery), and its surface-scoped `trusted_channel` grant (`registerTrustedChannelGrant`), so unmounted-channel traffic fails closed. Run policy middleware is registration-owned: `apps/openomni/src/composition/policy-registry.ts` holds per-run policy factories with declared mandatory/optional classes; the Resident builds each run's middleware from the registry, a missing mandatory policy (e.g. compaction, registered as a composer-owned stage) suspends the run fail-closed with a typed `MissingMandatoryPolicyError`, and the registry supplies run-tightening middleware only — admission verdicts remain solely with the gateway and delegation kernel. The shipped component events currently observe Resident/Worker invocation generations only.
- Connector installation/execution beyond retained protocol and storage primitives (#216 class).
- Memory.Engine / FTS5 session search (#220).
- P4 role surfaces (Governor, Jester, Voice).
- Stakes and effective-authority consumers; any such work must inherit their contracts rather than recreating legacy code.
