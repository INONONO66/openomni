> Project rule of thumb behind this file: an engine without a consumer does not count as shipped. "Built" and "wired" are tracked separately because the recurring failure mode here is completed schemas/stores that nothing calls.

## Foundation restructure target (2026-07-03)

The philosophy-v2 rewrite ([Design Philosophy](design-philosophy.md), [Core Model](core-model.md), [Architecture](architecture.md)) sets a structural target the component tables below do not yet reflect: three communication verbs (`ingress.submit` / `dispatch.submit` / `bus.publish`, subagent as the only non-gate path), one ledger (`WorkerRun` absorbed into `WorkItem.attempts`, target `Ledger.append(event, expectedHead)` as the serialized durable/CAS record-before-act write, `bus.publish` retained only for observation/projection, agent-greppable export), the policy engine relocated to ring 1 with per-point context schemas, and package renames (`session`→`ledger`, `openomni`→`kernel`). Migration runs in five phases (P0 dead-code clean → P1 one channel → P2 one ledger → P3 rings → P4 roles); the phase plan and the audit-confirmed extraction/merge/delete ledger live in [Architecture](architecture.md). The 2026-07 full-package audit confirmed ~5–6k LOC of dead code and 3 bugs (llm catalog refresh path, adaptStream v4 shim, resident definition drift). **P0 is complete**: #461 cleaned the coordinator/worker seam, #471 fixed the three bugs, #472 shipped the P0 conformance-gate increments, #473 completed the openomni/server/session/llm/agent dead-code sweep, #475 removed deprecated `AgentProfile.permissions`, and #476 completed the post-sweep hygiene pass. Roadmap SSOT: [#459](https://github.com/INONONO66/openomni/issues/459).

**P1 is complete**: #477–#481 shipped the worker-driver slice, #484 closed the policy-contract/three-verb enforcement scope, and #485 closed unified kernel routing. The only remaining #462 item is `@openomni/ipc` extraction, explicitly carried by P3 package rings rather than P1.

The 2026-07-05~07 design rounds (recorded as resolutions on the phase issues; summarized in #459 § Design resolutions) sharpened the target: decisions await the per-owner-key serialized/CAS `Ledger.append(event, expectedHead)` before acting, while `bus.publish` remains a lossy observation/projection surface (#455). That split is planned, not wired; current behavior is recorded in the component tables below. PendingAsk/PendingInteraction/WorkItem blockers/WorkerRun collapse into **one `Wait` primitive** with `ownerRef: workItem | session` (#215); executors implement **`Execution.Driver`** — `deliver` required, `send`/`cancel` capability-declared, uniform event projection of lifecycle + raw transcript + evidence (#462); inbound routing converges on **one kernel `resolveRoute` pipeline** whose decisions are published as observation events (#464), while #455 owns their future durable serialized/CAS recording; and the protocol vocabulary gets a diet plus a CI-enforced namespace ↔ Tier-2 review gate (#465). The coordinator/worker seam was the opening cut: PR #461 removed dead modules, write-only telemetry, and double ledgers and fixed an orphan-restart bug (~1.3k LOC net); #471/#472/#473/#475/#476 then completed the remaining P0 bug-fix, conformance, dead-code, deprecated-field, and hygiene work tracked by #453.

The 2026-07-09 **handoff-hardening round** (full issue-board audit for fresh-agent executability; recorded as body edits + dated comments on every phase issue) resolved the open cross-issue conflicts: #467's P0 exit is deliverable increments 1–3 only (lint-tools, round-trip, earned check) with the verifier registry and replay conformance co-landing with P2 #455; the hash chain stays on the write path with boot tail-verify only, and full-chain verification survives solely as #226's offline restore-drill gate; legacy WorkerRun/PendingAsk/PendingInteraction rows are frozen read-only + upcast-on-read on absorption (never dropped); the greppable export is derived JSONL (SQLite remains the source of truth); the stakes computation got its own issue **#469** (kernel-observed windowed state; consumers: evidence-gate threshold, Voice auto-reply, objection intensity); `policy/resolver` was removed from the P0 dead-code list (retained and wired by #462); and the Wait primitive plus the determinism/verification contract were promoted from the machine-local research doc into [Kernel Contract](kernel-contract.md) §6 so the normative ground is tracked.

The 2026-07-09 **determinism/verification round** (red-team + durable-execution + deterministic-verifier research; recorded in `docs/foundation-formal.local.md`, summarized in #459 § Design resolutions) reframed the target honestly: the kernel is an **accountability system, not a correctness system** — it makes agent behavior recorded, bounded, and replayable, it does not make outputs true (determinism ⊥ accuracy). `verify` now means *a deterministic verifier re-established a specific predicate* (stored with the verdict), never "true"; `guaranteed` stays reserved for the three code-enforced behaviors. New issue **#467** (kernel contract conformance gate) pulls the vocabulary-gate mechanization forward and adds tool-lint, protocol round-trip, a **sandboxed deterministic verifier registry** (four families, no LLM-judge; unverifiable claims are typed `asserted` and high-value ones raise to the Owner), and **replay conformance** keyed on a runtime+deps fingerprint — it is the test harness for the architecture and blocks the P1–P3 additions. The target attempt model gives every execution instance an immutable `attemptId` and per-WorkItem `attemptSeq`, with nullable `retryOf`; content/environment fingerprints, cache lookup, and replay identity stay separate so identical retries coexist. Per-key serialized compare-and-append, nondeterminism capture, and intent/reconciliation for external effects are also target P2 contracts, not current wiring.
