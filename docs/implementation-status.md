# Implementation Status

Single source of truth for the gap between accepted design and running code. Other docs (core-model, AGENTS.md, ADRs) link here instead of restating status inline.

**Legend**: ✅ implemented (runtime behavior is production-wired unless the row explicitly says contract/gate only) · 🔌 dormant — built and tested, zero production callers · 🚧 partial · 📋 designed, not implemented · Last verified: **2026-07-26**.

> Project rule of thumb behind this file: an engine without a consumer does not count as shipped. "Built" and "wired" are tracked separately because the recurring failure mode here is completed schemas/stores that nothing calls.

## Foundation restructure target (2026-07-03)

The philosophy-v2 rewrite ([Design Philosophy](design-philosophy.md), [Core Model](core-model.md), [Architecture](architecture.md)) sets the structural direction: three communication verbs, one authoritative ledger, the policy engine in ring 1, and eventual package renames. Migration runs P0 clean → P1 channel → P2 ledger → P3 rings → P4 roles. **P0, P1, and P2-04 are production-wired**: the strict native Work/Attempt/Wait ledger and closed projections are the only production durable path. **P2-05–P2-07, C1, P3, and P4 remain unshipped.** Roadmap SSOT: [#459](https://github.com/INONONO66/openomni/issues/459).

**P1 is complete**: #477–#481 shipped the worker-driver slice, #484 closed the policy-contract/three-verb enforcement scope, and #485 closed unified kernel routing. The only remaining #462 item is `@openomni/ipc` extraction, explicitly carried by P3 package rings rather than P1.

The Owner-approved revision-9 cutover is the production path. Server startup accepts only `p2-clean-v1`, opens one process-lifetime FULL writer, and synchronously rebuilds the closed projection catalog before admitting writes. Thin server composition then binds host dependencies to OpenOmni production semantic services under `packages/openomni/src/ledger/production/`; producers start only after credentials, explicit model environment/catalog, projections, and services validate.

P2-04 is a clean current-state baseline, not evidence that later P2 milestones shipped. P2-05–P2-07 still own export/replay artifacts, C1 end-to-end restart/refutation/reconciliation proof, and the remaining reconciliation/conformance work. #215 still owns complete existing-agent messaging semantics; #467 still owns verifier consumption and replay conformance; #469 still owns stakes consumption. P3 package extraction/naming and all P4 role runtime remain planned.
