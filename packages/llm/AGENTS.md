# packages/llm

LLM provider abstraction. Handles auth (API key + proxy), provider SDK wiring, streaming, retry, message conversion, token usage accounting, and the `run()` entry point. Depends on `@openomni/protocol` only. It reports what it did through an injected `BusEvent.Sink`, so it imports no implementation of the observation channel and nothing durable (#606).

## STRUCTURE

```
src/
├── index.ts          # Public API: Auth, Provider, ModelsDev, run, Run, RunInput, and Sink
├── run.ts            # run() + package-owned Run.Outcome; model/trace/events required
├── sink.ts           # Streaming callback contract: message snapshots and paired tool projections
├── error.ts          # Internal API/provider errors + coerceApiError (AI SDK error → typed APIError)
├── message/
│   └── index.ts      # toModelMessages() — Message.WithParts[] → AI SDK messages
├── processor/
│   ├── index.ts      # Processor.create() — bounded retry loop, transcript fold, sink/event projection
│   └── stream-events.ts # Stream event projection: text/reasoning/tool/step parts + bounded interruption cleanup
├── retry/
│   └── index.ts      # Retry.decide / sleep / instant-failure detection; typed finite backoff decisions
├── auth/
│   ├── index.ts      # Auth barrel
│   └── storage.ts    # Auth get/set/all; atomic mode-0600 credential writes
├── provider/
│   ├── index.ts      # Provider + ModelsDev public namespaces; internal provider helpers stay deep
│   ├── identity.ts   # clientIdentity() — the single owner of the `pi/<version> (<platform> <kernelRelease>; <arch>)` user-agent
│   ├── sdk.ts        # getSDK() + getLanguage() — maps Provider.Model to @ai-sdk/* instance
│   ├── transform.ts  # ProviderTransform — message normalization, caching, per-provider variants
│   └── proxy-models.ts # Proxy model catalog fetch/enrichment
├── token/
│   └── index.ts      # TokenTracker.extractUsage + estimateUsage (local usage estimator port)
└── model/
    ├── index.ts      # ModelsDev.get — fetches models.dev catalog (lazy helper inlined here)
    └── models-snapshot.json # Bundled trusted catalog snapshot — the weekly workflow regenerates THIS file (#471)
```

## KEY PATTERNS

- **Narrow root public API**: `src/index.ts` exports only `Auth`, `Provider`, `ModelsDev`, `run`, package-owned `Run`, `RunInput`, and the `Sink` type. Errors and helpers remain internal. Do not add session/protocol helpers, `ProviderTransform`, proxy-model helpers, `Processor`, `Retry`, message conversion, or `TokenTracker` to the root barrel.
- **`run()` entry point**: Takes `RunInput` (messages, tools, required model, non-empty required `trace`, required `events`, optional auth, optional transport, system, toolExecutor, toolChoice, step/window/steering yield controls, `maxRetryAttempts`, providerOptions) plus a `Sink`, drives a Processor loop, and returns the package-owned `Run.Outcome`. It disables AI SDK retries (`maxRetries: 0`) because Processor owns transport retry; callers may set `maxRetryAttempts: 0` when a higher layer, currently Agent, owns attempts and backoff. Standalone callers retain Processor's finite default. `RunInput.model` is required; do not reintroduce model-less/noop fallback behavior.
- **Provider.Model**: Zod schema carrying only consumed catalog metadata — identity (`id`/`providerID`/`name`/`family`), SDK routing (`api.npm`/`api.url`/`api.id`), and `limit.context`. `status`/`release_date` were stored by `fromModelsDevModel()` and read by nothing; both are gone from the schema, the mapping, the proxy stub, and the `ModelsDev.Model` input shape (a re-add without a reader fails `test/provider/integration.test.ts`). Built from `models.dev` data via `Provider.fromModelsDevModel()`; `Provider.listModels()` is the catalog lookup. Fields models.dev publishes but nothing here reads (capabilities, cost, options, headers, modalities) are deliberately absent — re-add one only together with its reader.
- **Auth.Info** (discriminated union): `{ type: "api", key }` | `{ type: "proxy", baseURL, apiKey? }`. `Auth.set()` writes the credential file atomically with mode `0600`; malformed JSON fails loudly so a later write cannot erase credentials. `run()` uses explicit auth first and otherwise reads `Auth.get()` unless `allowAuthFallback` is false.
- **SDK wiring** (`provider/sdk.ts`): `getSDK(model, auth, transport?)` resolves bundled Anthropic/OpenAI or an explicit OpenAI-compatible endpoint. SDK and language-model caches are bounded LRU maps; keys include provider/package/URL, a SHA-256 auth fingerprint, and a transport fingerprint (two callers differing only by a tenant header must not share an instance), while the language cache additionally includes model id. Raw credentials never appear in cache keys.
- **Client identity** (`provider/identity.ts`): every SDK instantiation defaults `headers["user-agent"]` to `clientIdentity()` — exactly `pi/<version> (<platform> <kernelRelease>; <arch>)`. The default is spread FIRST, so provider-specific and operator headers override it by name. The version is a constant pinned against `package.json` by test (this package has no `dist/`, but the module is imported from both trees by consumers). One owner: do not set a user-agent at a call site.
- **Operator transport** (`RunInput.transport`): optional `{ baseUrl?, headers? }`, resolved by the HOST from its own config and handed down like `auth` — the package reads no environment for it. `baseUrl` outranks the catalog's `api.url`; proxy auth outranks both, because a proxied credential is minted for one endpoint. Headers merge over the client identity. Provider-specific behavior belongs in `provider/`, `auth/`, or `transform/`, not in call sites.
- **Provider transforms** (`provider/transform.ts`): `normalizeMessages()` filters empty blocks and sanitizes tool-call IDs; `applyAnthropicCaching()` marks ONLY the latest user message (1h TTL) — the system and last-tool breakpoints are marked by `run.ts` via `anthropicCacheOptions` (#532 policy: three of the four allowed breakpoints at the stable→volatile seams). This is an internal/deep import surface, not a root export.
- **Sink**: Public callbacks are `onMessage`, `onToolCall`, and `onToolResult`. The unused public `onFact` tap and processor/agent forwarding were removed in U967.5; no alias replaces it. Internal transcript folding still assembles immutable messages and enforces fact ordering.
- **Processor**: Created via `Processor.create({ assistantMessage, sessionID, model, abort, trace, events, sink?, createStream, toolNames?, maxRetryAttempts?, estimateUsage? })`. `trace` and `events` are required. `process({ system, promptText })` resolves on stream completion and throws on abort/terminal error; `run()` maps that to `Run.Outcome` and publishes one terminal LLM event for every start. Each retry gets a fresh transcript attempt id; failed attempts close before the next begins, while usage totals include all billed attempts. Folded snapshots are immutable and emitted at part boundaries, not per token delta. Tool names are provider-safe on the wire and mapped back to their original dotted names in transcript facts. Processor owns tool stream projection; tool execution happens only in `run()`'s AI SDK callback. Operational status is `busy` → (`retry`…) → `idle`, exactly one `idle` per process call.
- **Retry**: raw AI SDK errors (`AI_APICallError`) must pass through `coerceApiError` before classification — their retry fields live on the error object, not under `.data`, and never match `APIError.isInstance`. The one entry is `Retry.decide(attempt, error)` → a typed `Decision` (`retry` with reason + delay, or `stop`): classification sniffs payload (message, then responseBody), then statusCode (429 / ≥500), then the provider `isRetryable` flag; delays respect `retry-after` / `retry-after-ms` headers up to 60s — an explicit directive ABOVE the cap is a fail-fast decline, not a clamp (only an inferred ratelimit-reset demotes to backoff) — with headerless backoff capped at 30s and jittered by `1 - random*RETRY_JITTER_RATIO` (server-directed waits are never jittered). Quota/balance exhaustion (`insufficient_quota`, `quota exceeded`, `out of budget`, `billing`, `monthly usage limit`) classifies as the TERMINAL reason `billing`, ahead of the provider's `isRetryable` flag, the transport-streak probe, and any retry-after — it sits outside `RetryableReason` on purpose, so the processor's exhaustive RateLimited switch stays closed. Provider moderation verdicts (`content_policy_violation`, `content_filter`, `content policy`, `safety filter`, moderation-blocked prose) on a 4xx classify as the TERMINAL reason `content_policy` — 5xx is excluded on purpose so a moderation backend outage keeps its retries. Anthropic's capacity signal `quota_exhausted` stays transient (`overloaded`). `Retry.classifyFailure(error)` is the entry for callers OUTSIDE the loop (hosts deciding what to tell a user): it coerces raw SDK errors, walks up to 8 `cause` links, and returns the same closed `Reason` vocabulary — hosts must import it rather than re-matching provider prose. The pre-#544 `Retry.delay`/`Retry.isRetryable` members are GONE — their absence is pinned by `test/retry/retry.test.ts`. Processor retrying is finite by default; do not use unbounded retry loops or publish `Number.MAX_SAFE_INTEGER` as a retry cap.
- **TokenTracker**: Extracts token usage from AI SDK/provider responses. Runtime accounting stores token counts on the assistant message, keyed by that message's provider/model identity. The llm package does not calculate dollar cost.
- **Usage accounting is provider-plus-local** (kernel §5.3): `extractUsage` returns the required `inputTokens`/`outputTokens` as `number | undefined`, where `undefined` means the provider's accounting for that field is UNUSABLE — the key was absent, its value was not a number, or the number was out of the count domain (NaN, infinite, negative, fractional, unsafe). A reported numeric `0` is usable and stays authoritative; alias resolution keys on PRESENCE, so neither a legitimate `0` nor a contradicted field falls through to a lower-priority alias. Unusable accounting never throws: the step-finish fold substitutes the injected `estimateUsage` port field-wise, whose shipped default is deterministic `ceil(chars / 4)` over the step's serialized prompt (input) and the step's emitted assistant text including tool-call JSON (output). `run()` owns the prompt serialization and passes it as `promptText`. The estimator's output source resets at each step finish, so multi-step totals stay additive. Optional reasoning/cache counters keep their `?? 0` defaults; do not reintroduce a zero default for the required counts, and do not add a typed usage error — an unaccounted step must fold, not abort.
- **ModelsDev**: Lazy-loads a sanitized on-disk catalog, otherwise fetches `models.dev`, and falls back to the bundled snapshot. Respects `OPENOMNI_MODELS_URL`, `OPENOMNI_MODELS_PATH`, and `OPENOMNI_DISABLE_MODELS_FETCH`. Remote/cache data is untrusted: only bundled provider packages are exposed, provider API URLs and model-level provider overrides are stripped, and prototype keys are refused. Proxy model discovery fails loudly on transport/HTTP/JSON errors and enriches only model ids the proxy actually returns.
- **Two bundled providers**: `@ai-sdk/anthropic`, `@ai-sdk/openai`. Custom OpenAI-compatible endpoints must come from explicit `Provider.Model` config, trusted bundled snapshot data, or proxy auth.

## ANTI-PATTERNS

- Do NOT import `Bus` here. `llm` reports through the `events` port it is handed; reaching for the process-wide bus re-couples the package to an implementation the composition root is supposed to choose (#606). `check-deps` carries a separate `srcAllowedDeps` for this package — `src/` may import `@openomni/protocol` and nothing else, even though the manifest lists `telemetry` for the tests.
- `packages/llm` sets `noEmit: true` in tsconfig — it does NOT produce a `dist/`. It is consumed as source by Bun.
- Do NOT raise `lib` in `tsconfig.json`. `main` points at `src/index.ts`, so `agent` and `server` pull this package's sources into their own programs under their own `lib: ["ES2020"]` — widening here would let an ES2022 builtin pass llm's gate and surface as an error attributed to a consumer. The test tree, which nothing imports, is checked separately by `tsconfig.test.json` at ES2022; `check-types` runs both.
- Do NOT add provider-specific logic to call sites. Keep SDK wiring in `provider/`, credential handling in `auth/`, and message/request shaping in `transform/`.
- Do NOT bypass `Auth.get()` for credentials (e.g. reading env vars inline). All credentials flow through the namespace.
- Do NOT hand-craft provider-specific request rewriting at call sites — keep it behind provider or transform modules so it stays in one place.
